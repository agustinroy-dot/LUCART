
## 2024-05-18 - [Quotes N+1 Query]
**Learning:** Found an N+1 query issue in the Quotes index route (`/app/quotes/routes.py`) where the template accessed `quote.customer.name` inside a loop, triggering a separate query for each quote. Fixed by eager-loading with `joinedload(Quote.customer)`.
**Action:** Always inspect Jinja template loops over database models for relationship accesses and ensure those relationships are eager-loaded in the route's SQL query using `joinedload`.
## 2026-06-13 - [Memory-Efficient CSV Streaming Export]
**Learning:** The previous naive CSV export approach buffered the entire unpaginated query result into memory, constructed a single massive CSV string using `io.StringIO()`, and returned it all at once via a standard Flask `Response`. This caused severe RAM spikes (e.g., ~19MB for just 10k rows) and risked OOM errors. Using SQLAlchemy's `.yield_per()` in combination with a custom generator and Flask's `stream_with_context()` keeps the memory footprint completely flat regardless of row count.
**Action:** When writing data export endpoints that return CSV, JSON, or other large serializations, always use a generator that writes to a temporary buffer, yields, and then truncates the buffer alongside a database cursor batching method like `yield_per()`. Additionally, wrap the response in `stream_with_context()` to ensure the database session stays active while streaming.
