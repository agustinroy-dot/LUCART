
## 2024-05-18 - [Quotes N+1 Query]
**Learning:** Found an N+1 query issue in the Quotes index route (`/app/quotes/routes.py`) where the template accessed `quote.customer.name` inside a loop, triggering a separate query for each quote. Fixed by eager-loading with `joinedload(Quote.customer)`.
**Action:** Always inspect Jinja template loops over database models for relationship accesses and ensure those relationships are eager-loaded in the route's SQL query using `joinedload`.
## 2024-05-18 - [AppSetting Request Caching Optimization]
**Learning:** Found that accessing multiple `AppSetting.get(key)` calls inside routes (like quotes calculator or settings index) resulted in individual N+1-style queries per setting per request. Wrapping setting reads in a `flask.g.app_settings_cache` scoped context cache reduces these N queries into a single application-wide fetch per request, improving read time by ~150x. Additionally, when restoring accidentally modified files during development, `git checkout HEAD <file>` is necessary since referencing `master` fails on dynamically generated task branches.
**Action:** When working with global setting models or configurations stored in databases, implement request-level caching (e.g., using `flask.g` in Flask) and lazy-load/warm the cache on the first read. Always ensure `has_app_context()` checks are in place to prevent breaking CLI or test environments. Use `HEAD` for safe file restorations instead of assuming branch names.
