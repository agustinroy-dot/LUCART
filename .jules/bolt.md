
## 2024-05-18 - [Quotes N+1 Query]
**Learning:** Found an N+1 query issue in the Quotes index route (`/app/quotes/routes.py`) where the template accessed `quote.customer.name` inside a loop, triggering a separate query for each quote. Fixed by eager-loading with `joinedload(Quote.customer)`.
**Action:** Always inspect Jinja template loops over database models for relationship accesses and ensure those relationships are eager-loaded in the route's SQL query using `joinedload`.
## 2024-07-08 - Flask Request-Level Caching with `g`
**Learning:** Adding request-scoped caching using Flask's `g` object for database lookups in a `@staticmethod` correctly resolves N+1 lookup problems on repeatedly fetched elements like configuration values (`AppSetting`). When doing this caching within a model, it must gracefully degrade using `has_app_context()` so that tests and CLI commands running outside a request context do not fail. Using `db.session.query(Model).delete()` is required when testing with a file-based SQLite database instead of dropping the DB file, as pooling holds the file handle open.
**Action:** When implementing application configuration models, evaluate the feasibility of request-level caching inside `get()` and `set()` using `flask.g` wrapped in `has_app_context()` to eliminate redundant database I/O for globals that are frequently queried (e.g. loops or layout templates). Always use query resets (`query(Model).delete()`) rather than deleting physical database files when testing connection-pooled databases like SQLite.
